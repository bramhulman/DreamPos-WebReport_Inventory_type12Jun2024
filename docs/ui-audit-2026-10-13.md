# Audit UI DreamPos Inventory

Tanggal: 13 Oktober 2026 (Asia/Bangkok).

## Cakupan

107 file ASPX dan 8 master page diperiksa dari source. 84 halaman terdaftar sebagai Content di proyek Visual Studio; 23 file lainnya tetap diinventarisasi, tetapi status penggunaan/publish perlu dikonfirmasi. Folder backup di luar DreamPos-WebReport tidak termasuk aplikasi ini.

IIS localhost:57116 belum berjalan saat pemeriksaan. Audit ini belum memverifikasi screenshot, overflow desktop/mobile, perilaku browser, atau data produksi. Penanda otomatis adalah kandidat pemeriksaan, bukan bukti bahwa setiap halaman rusak. Kode yang dikomentari disaring untuk penanda DataTables, .live(), dan alert. Penanda kosong juga bukan sertifikasi visual.

## Temuan Utama

1. **P1: jQuery halaman mengganti instance master.** Master inventory memuat jQuery 3.6.0 dan plugin. 37 halaman proyek masih memuat jQuery 1.x/2.x, biasanya melalui HTTP. Plugin dapat hilang setelah jQuery diganti; HTTPS dapat memblokir asset HTTP. Contoh: Pages_ReceipeEdit.aspx:17, Pages_ItemMaster.aspx:28, Pages_CPOEdit.aspx:57. Ada 31 halaman dengan .live(); penggantian script harus disertai migrasi event ke .on() dan pengujian autocomplete, modal, export, serta postback.

2. **P1: dependensi DataTables dan plugin berulang.** 26 halaman proyek memuat core DataTables sendiri padahal master sudah menyediakan core. Versi/CSS tidak selalu seragam. SiteInventoryHome.Master:27-64 juga memuat Moment, daterangepicker, Knob, dan Summernote berulang. Gunakan satu sumber core di master dan extension yang diperlukan di halaman.

3. **P2: lebar form tetap.** 43 halaman memiliki kandidat width/min-width besar. Contoh nyata: Pages_StkGroupEdit.aspx:109 memakai width:800px di col-md-3; Pages_CPOEdit.aspx:15 dan Pages_ReceipeDtlEdit.aspx:12 memasang width:800px pada input-group. Periksa desktop dan mobile 390px, termasuk label panjang dan validasi. Ubah mengikuti grid setelah screenshot dikonfirmasi.

4. **P2: kesiapan DataTables.** Dari 26 halaman dengan inisialisasi DataTables aktif, 20 belum memiliki initComplete/processing readiness hook eksplisit. Spinner postback belum menjelaskan apakah tabel siap. Prioritas: Stock, Item Master, List Opname, Closing Stock. Indikator tambahan mungkin tidak diperlukan untuk tabel kecil yang sudah memakai paging server. Acuan dengan hook: Inventoryhome, Daily Opname, InvBatch, InvRcv, InvReturn, kstock.

5. **P2: wrapper responsif.** Pages_InvOrderWDetailRcv.aspx dan User_Edit.aspx memiliki data control tanpa table-responsive di markup halaman. Halaman lain tetap perlu inspeksi screenshot untuk memastikan setiap tabel, bukan hanya satu tabel, berada di wrapper yang sesuai.

6. **P2: kelas Bootstrap 5 pada Bootstrap 4.** Inventoryhome memakai fw-bold, text-end, ms-*, dan me-*; bundle lokal adalah Bootstrap 4.3.1. Halaman sudah menyediakan CSS khusus untuk text-end, sehingga kelas tersebut bekerja. fw-bold serta utilitas margin ms-*/me-* masih perlu dicocokkan dengan CSS aktual atau diganti font-weight-bold, ml-*, dan mr-* secara terarah.

7. **P2/P3: pesan dan state.** 82 halaman proyek memiliki alert() aktif di client atau code-behind; sebagian merupakan pesan login/redirect. Angka ini tidak berarti 82 halaman mengalami error. Standarkan error/sukses dengan Bootstrap alert/toast dan periksa loading, error, dan empty state per workflow.

8. **P3: master lama.** Inventory.Master tidak memiliki viewport. SiteHome.Master memuat DataTables sebelum salah satu jQuery dan memuat jQuery lagi di footer. SiteReport.Master memuat Bootstrap 4.0.0 dan 4.3.1. Pada 84 halaman proyek, 77 memakai SiteInventoryHome.Master, satu SiteReport.Master, satu SiteLogin.Master, dan lima standalone. Prioritaskan inventory aktif sebelum master yang status penggunaannya belum jelas.

## Improvement Backend Tahap Ini

Query cost centre sekarang berparameter, mengabaikan ID kosong/tidak valid, menghilangkan duplikasi ID, mempertahankan customer/outlet scope, dan menutup koneksi dengan Using. Pencarian stock group memakai parameter dan mengelompokkan OR agar customer tetap berlaku. Stock Group Edit memuat data sekali, dan tidak menjalankan query edit untuk record baru.

Recipe Edit memeriksa tabel hasil sebelum akses Tables(0), menampilkan Bootstrap error, dan menonaktifkan save bila load gagal. Cancel recipe menggunakan Redirect(..., False) serta CompleteRequest agar redirect biasa tidak tercatat sebagai ThreadAbort error. Pencarian cost centre di DataView juga menangani tanda petik pada nama.

Rebuild tidak dijalankan sesuai .antigravityrules. Parser VB terhalang dependency assembly lokal; validasi compile/semantic tetap perlu dilakukan user di Visual Studio. Database tidak diubah untuk pengujian tahap ini.
